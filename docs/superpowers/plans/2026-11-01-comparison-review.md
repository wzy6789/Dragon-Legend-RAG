# 实验台对比阅读与过程审阅

**目标**：让用户保持 A 左、B 右阅读两份答案，在同一行比较评分维度，并能从公开执行阶段追溯原始事件。沿用已授权的实验工作台方案。

**实现选择**：沿用 Next/React 和已有评分、事件契约；用对齐的双列条形图及明确数值分差，替代互相分离的七维图。无需添加图表依赖。过程以可展开阶段卡片呈现，原始事件按原序保留。

**约束**：保持黑色视觉、版本接线、历史记录、BYOK 和后台运行机制；不触发模型调用。缺失不计零分，部分完成不能判胜，未知量尺不能计算分差，不重算封顶总分，不暴露模型私有思维链。无装饰箭头。

## 实施与验收

- [x] 评分比较：完善 `workbench.compareResults` 对部分完成、无效量尺和越界总分的保护；在 `lib/score-comparison.ts` 对齐维度。测试有效零分、缺失、异协议/裁判、未知量尺、删除 A 后的 B 身份及权重差异。
- [x] 对比界面：新增 `ScoreComparison`，支持协议顺序/分差顺序、仅看差异、缺失维度提示；保持 A/B 位置；从对应侧直接打开评分详情。
- [x] 过程界面：阶段卡片默认精简，展开查看原始事件；重复检索轮次、原始时间、不完整状态均保留。公开阶段不冒充推理链或成功证明。
- [x] 详情跳转：对比页直接打开评分/过程/证据标签，不再总落到概览；关闭详情不改变任务运行。
- [x] 浏览器验收：桌面双栏、窄屏滚动、200% 放大、键盘、差异筛选、评分失败、部分完成、评分/证据/过程跳转、事件展开、切换视图不丢答案阅读位置。
- 发布门槛：前端测试、类型检查和生产构建通过；模拟数据验证后发布，真实官网核对静态页面与知识库健康状态，不执行付费问答。

## 审阅重点

1. 总分 100 与逐维 10 的量尺独立；总分和七维不相互推导。
2. 重评失败不能回退旧分装作当前成功；缺失值不能显示为平局。
3. 初始 A 被删除后 B 不能改名为 A。
4. 过程只读已有公开元数据；不能从相邻上报推算阶段耗时或填补不存在的阶段。
5. 详情打开后不取消生成，不打断左右答案的独立阅读位置。
